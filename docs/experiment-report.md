# 单实验带证据报告

## 首版范围

`papertrace.experiment_report.build_experiment_report` 将现有单篇问答按固定字段组织为 JSON 兼容字典。调用方指定一篇论文和一个明确实验范围，例如“Transformer base，WMT 2014 English-to-German，单模型”。每字段独立检索并复用 `answer_question` 的片段选择及引用定位检查，不增加检索算法或另写抽取模型。

这是字段化证据报告，不是恢复完整实验表格，也不是已验收的数值数据库。默认字段内容仍为带引用的结论列表；结果字段可显式启用下述关系图协议，单独记录主体、成绩、条件及证据。实验范围是调用方描述，程序不证明该实验存在，不自动拆分多实验或验证跨字段一致性。只提供 Python 函数，不新增CLI、网页、渲染器或自动文件写入。

## 字段与结构

默认生成以下7类，也可通过 `fields` 指定非空、无重复的子集：

| 字段名 | 内容 |
| --- | --- |
| `research_question` | 研究问题或实验任务 |
| `datasets` | 数据集、语言对、划分与预处理 |
| `model` | 被评价的模型及具体变体 |
| `baselines` | 对照方法及比较条件 |
| `training_settings` | 硬件、优化器、批大小、步数/epoch |
| `evaluation_metrics` | 指标与评测过程 |
| `results` | 带模型、数据集、划分、指标、数值、单位与条件的结果 |

输出的 `sections` 为有序列表，每项有 `field`、中文 `label` 和完整 `qa`。`qa` 沿用问答schema v2，含结论、引用、候选、缺失及生成元数据，详见[带证据问答](evidence-qa.md)。`E1.S1` 等局部编号仅在本字段内有效，不合并证据表。

顶层保存报告版本、指定论文/范围、论文分块指纹、字段查询计划哈希、抽取策略哈希、逐状态字段数及用量。当前报告版本为 `experiment-report-v5-result-condition-policy`，复核版本为 `experiment-scope-review-v3-result-condition-policy`；每字段 `qa.query` 记录生成任务JSON，`qa.retrieval_query` 记录实际检索文本，`qa.system_prompt_sha256` 记录实际系统提示哈希。`qa.scope_review` 记录逐条判定、保留的原结论索引、移除数量、复核提示哈希和用量；`claim_audit` 保存全部原结论（包括被过滤项）、其精确引用、绑定上下文、判定理由和 `included_in_final_claims`。审计内容是经结构校验的模型生成数据，不是已验证事实；展示最终答案应只使用 `qa.claims`，不可把审计重新合并进答案。不设统一“报告完整”状态：所有字段 `answered` 也不证明全文抽取完备。报告含候选原文、原生成结论和模型复核理由，仍可能包含范围外或错误内容，保存或公开需考虑隐私和原文使用范围。

## 证据边界

固定抽取规则通过可信应用系统指令传递，实验范围、字段与问题作为用户消息内的JSON数据传递，不将范围内容插入系统指令。规则要求每条结论同时属于指定实验和字段；只有范围外信息时无结论并返回 `insufficient`，不能把其他变体的设置、其他任务成绩或开发集成绩当作目标内容，即使带免责声明也不纳入结论。共用设置需有适用于目标变体的候选依据；数字保留单位与条件；不从混乱表格推测行列、不计算新结果、不借外部知识补全。关系或范围不明确时列出缺口。这些是行为提示，不是语义验证，也不是完整提示注入防御。

结果字段将成绩与必要评测条件视为同一可核验结果：测试划分、单模型/集成、checkpoint选择或平均、解码/搜索设置均可纳入，也可与 `evaluation_metrics` 重叠。抽取规则要求在同一条结论引用表格与正文的多个片段以支持关联，不借其他结论的引文。条件必须明确适用于目标变体或明确涵盖目标的共用实验设置，不能仅凭相邻、同篇或“we used”字样推断适用。GPU、耗时、FLOPs、优化器等纯资源/训练内容仍不纳入结果字段。

成绩有据但必要条件缺失或关联不明时，提示要求保留有据部分，以 `partial` 及 `missing_info` 表明缺口；只有条件没有成绩时同理。复核不因条件不是指标或未重复模型名称而自动排除，也不自动补写条件。结论声称无依据条件时仍整体拒绝。这些覆盖与关联要求由模型判断，程序没有条件槽位、完整性检测器或自动语义修复；模型误判仍可能通过结构校验。

检索仅使用“实验范围＋换行＋字段问题”，不包含公用抽取规则、JSON字段名或参考答案。查询缓存必须按实际文本匹配。报告默认 `preserve_source_candidates=True`：混合检索使用 `search_candidates` 保留两路各Top-K的去重并集，仍按RRF排序但不再截断为K条，最多2K条（默认10条），不扩大单路深度或新增向量请求；`False` 可显式使用旧融合Top-K。单路工厂没有并集入口时仍使用普通搜索。每字段记录实际 `retrieval_policy`、`candidate_limit`；`top_k` 在并集模式下指每一路深度，不是最终证据数量。字段候选可重复，不能认为遍历了全文。更多候选会增加输入成本、干扰和超限概率；表格结构仍可能丢失，见[解析观察](text-parsing-observations.md)。

有生成结论时增加一次逐条范围/字段/直接支持复核，向复核模型发送任务、各结论自己的精确引用及程序绑定的 `citation_context`，不发送金标或参考答案。上下文仅来自本条实际引用的原始分块（按来源去重），不借用其他结论或未引用候选；保留分块身份、页码及完整字符范围，类型为 `bound_full_chunk_context`，与模型选中摘录明确区分。该上下文可支持标题、列头、任务及条件归属，但不证明表格行列已可靠恢复；复核提示仍要求关系明确，否则不猜测，并拒绝同时混合范围内/外信息的结论。抽取提示要求表格结果同时引用标题/列头/数据行，或使用现有整块兜底；通用QA原片段编号和提示不变。

复核仅可返回 `keep/out_of_scope/unsupported/uncertain`，程序仅保留 `keep`，选中引用原样保留，不自动把短引用替换为整块或生成替代答案；部分被移除则降为 `partial`，全部被移除则为 `insufficient`，原有缺失项不被清空。`support_basis=selected_quotes_and_bound_source_chunk_context` 如实标记复核依据：短摘录本身仍可能不自包含，完整上下文需在审计中查阅。无结论时跳过复核。缺判、重判、乱序、非法JSON、截断及组件失败均使报告失败，不退回未经复核的答案，也不自动重试。审计仅在整个报告成功时返回，不新增自动落盘；失败正文或半份报告仍不保留。缺失列表中的自由文本、证据候选、审计及复核理由未经过同样语义过滤。

各字段保留 `answered/partial/insufficient`，缺失只针对候选，不等于论文未报告。顶层将语义支持、实验范围匹配、跨字段一致性与穷尽性均标为 `not_verified`；没有候选时不调用模型。

## 使用与费用

### 可选结构化结果模式（v7）

调用 `build_experiment_report(..., result_target=...)` 可对 `results` 字段启用 `experiment-report-v7-multikind-coverage`。其余字段以及不传该参数的报告保持v5流程。目标由调用方显式填写，不从自然语言范围中自动解析或自动猜测别名；自然语言范围与结构化目标应由调用方保持一致。该参数必须与包含 `results` 的字段集合一起使用。

```python
result_target = {
    "model": "目标模型的规范名称",
    "task": "目标任务",
    "dataset": "目标数据集",
    "split": "目标测试划分",
    "model_type": "single",  # single或ensemble
    "required_conditions": ["model_selection", "checkpoint_averaging", "decoding"],
}
# 在下方build_experiment_report调用中传入result_target=result_target。
```

这只是接口示例，不是已执行的真实请求。必填身份五项均为有界非空文本，`required_conditions` 为无重复列表，可选类型为 `model_selection/checkpoint_averaging/decoding/evaluation_protocol`，也可为空。模型返回主体身份中未知字段为 `null`（`model_type` 为 `unknown`），不会由目标值补齐。目标不能含参考成绩或checkpoint数值。检索仍使用原“自然语言范围＋字段问题”，结构化目标只进入生成/复核任务数据，不进入检索词或系统指令。

一次生成返回 `subjects/results/conditions` 三类节点，不再返回自由结论文本。每类最多20项，字段、ID、引用均严格校验：

- 主体：`subject_id`、五项 `identity`、支持身份的 `citations`。
- 成绩：`result_id`、`subject_id`、`metric/value/unit`、`citations`；单位可为 `null`，数值为原文字符串。
- 条件：`condition_id/kind/value`、主体集合 `applies_to`、成绩集合 `result_ids`、内容 `citations`、关联依据 `applicability_citations`，以及逐类别证据 `coverage`。

引用仍只由模型选择本次片段ID，程序回填原文、论文、页码与块内偏移。指标/值/单位和条件值必须原样出现在本节点选中的片段中，但原样出现不证明列对应或语义支持。所有关系必须指向已有ID；悬空、重复ID、重复引用、未知片段、非法槽位/JSON均使本字段失败，无重试或半份报告。

程序仅投影五项主体身份与显式目标逐字完全一致的成绩。条件必须同时连到该成绩和该主体，才进入该成绩的条件列表；只连一个、连到另一主体或归属不明时不补边。共享设置允许显式关联多个主体。缺少调用方要求的条件类别时，由程序生成固定缺口并保持 `partial`；无目标成绩为 `insufficient`。自由结论文本不再由模型提供，而由通过检查的槽位生成，以减少“槽位是base、正文写big”的内部不一致。

v7中一个条件可显式覆盖多种类别，例如：

```json
"coverage": [
  {"kind": "model_selection", "citations": [{"segment_id": "E2.S1"}]},
  {"kind": "checkpoint_averaging", "citations": [{"segment_id": "E2.S1"}]}
]
```

该示例只有在实际条件片段确实同时支持两类时才有意义，不是固定模板答案。每项为固定类别和本条件的片段引用，至少一类、最多四类且不重复，须包含条件主 `kind`。逐类别引用必须是条件自身 `citations` 的子集，不可借用主体、关联依据或其他条件中的引文。一个条件只展示一次原文，多类以标签并列；不同条件支持同类时覆盖只计一次，审计保留各个来源。只有连到本次目标主体和成绩的条件才贡献覆盖，类别标签不绕过身份或边检查。

兼容没有 `coverage` 的旧条件输出：只归一化为主 `kind` 的一项覆盖，标为 `coverage_origin=legacy_primary_kind_only`；显式新输出标为 `explicit`。不从身份、原文关键词或类别之间的经验关系自动推断额外覆盖，不强制复制条件节点。`result_audit` 与最终成绩的 `condition_coverage` 按类别记录贡献的条件ID、来源类型及精确引用；其 `basis=declared_condition_labels_with_local_reference_checks` 只说明检查机制，不表示标签语义已验证。原v6运行记录和原 `partial` 状态保持不变。

投影复用原QA定位校验及一次范围复核；复核错误keep也不能恢复此前因主体/边不匹配而被排除的节点。`qa.result_graph.final_results` 是复核后最终成绩，含主体、入选条件和缺失类型；`nodes/result_audit` 是全部结构有效模型节点及投影审计，可能含错误或范围外内容，不作为最终答案。`qa.claims` 仍供原接口展示，内容由相同投影产生。最终节点与审计深拷贝隔离；没有候选时不调用生成，图状态为 `not_generated_no_evidence`。

`result_graph_policy_sha256`、`qa.system_prompt_sha256` 记录实际图抽取提示；结构化目标也进入字段任务与计划哈希。报告层原 `extraction_policy_sha256` 仍记录其他字段使用的旧规则，不代表结构化结果提示。结果生成版本为 `result-graph-v2-multikind-coverage`，普通QA版本及提示不变。`result_graph` 安全诊断阶段的固定细分码为 `content_invalid/json_invalid/fields_invalid/nodes_invalid/identity_invalid/references_invalid/links_invalid/literal_invalid/coverage_invalid`，不输出动态ID或原始失败正文。非法覆盖类别/重复/字段及跨条件借用合法片段为 `coverage_invalid`；覆盖中的不存在、重复或格式错误引用仍为 `references_invalid`。

这些检查只约束模型声明的身份和关系。模型可能把big规范化成base、给错误条件贴目标ID、选择含多个变体的整块，或提供并不支持关联的合法引文；也可能给有效引文贴上它不支持的类别。这些语义错误仍可能通过。因此 `source_entailment`、身份规范化、条件适用性及 `condition_coverage` 均标记未验证，字面槽位匹配不是事实验证；同类型条件相互冲突、证据穷尽性及全篇完整性也未自动解决。要求条件类别齐全只是结构覆盖，不证明条件正确。v6已有下述单次开发回归；v7尚无真实生成回归，尚无独立质量验证。

```python
from papertrace.experiment_report import build_experiment_report, ReportError
from papertrace.generation import DeepSeekGenerator
from papertrace.keyword_search import KeywordRetriever

# chunks由既有分块流程加载，此处不重新读取PDF。
report = build_experiment_report(
    "attention_is_all_you_need",
    "Transformer base on WMT 2014 English-to-German, single model",
    chunks,
    retriever_factory=KeywordRetriever,
    generator=DeepSeekGenerator(),
    fields=["datasets", "training_settings", "results"],
    top_k=5, max_tokens=2048,
)
for section in report["sections"]:
    print(section["label"], section["qa"]["status"])
    print(section["qa"]["claims"], section["qa"]["missing_info"])
print(report["generation"])
```

示例执行可能计费，不是已执行的真实报告。关键词工厂不调用向量API；混合工厂可沿用问答说明，按传入单篇分块建立合法子快照。

完整报告默认7次字段检索，最多14次生成接口调用（每字段抽取一次、有结论时复核一次）；三字段回归最多6次。使用混合/向量检索且没有查询缓存时，每字段还可能产生一次查询向量请求，并集本身不新增请求。生成调用数不是HTTP数；自定义客户端内部行为由调用方负责，当前DeepSeek适配器每次最多发送一次，不重试。抽取与复核用量均计入汇总，具体用量分别保留在 `qa.generation` 与 `qa.scope_review.generation`。报告层不重试、不自动修复或补检索。

v4绑定整块上下文不新增模型调用，但会增加复核输入tokens、报告体积及提示注入表面；同一块用于多条结论时会分别传递。复核上下文仍限制为64000 UTF-8字节，超限直接失败，不静默裁剪或自动扩大预算。

`generation_calls` 为生成接口次数；`known_usage_subtotal` 汇总合法统计；任一用量未知或没有生成时，`total_usage=None`，`unknown_usage_calls` 记录未知数量。统计不含向量请求、不代表账单；顶层只汇总输入/输出/总tokens，缓存统计保留在各字段。自定义生成器返回非法非空用量会被拒绝。

## 失败与验证

字段名、范围、参数及语料在首轮检索前检查；后续字段错误/大小上限不能全部提前预测。任一字段失败立即停止，抛出 `ReportError`，不返回或落盘半份报告。之前调用可能已计费，重新执行不复用已完成生成。安全诊断含失败字段、完成数、生成用量小计及净化的问答错误，不含问题、候选或答案。`cause.validation_stage` 和 `cause.detail_code` 在已细分的校验失败时记录固定白名单码，区分抽取答案与范围复核阶段；未细分时这两个键缺省。完整码表见[问答诊断说明](evidence-qa.md#输出与追溯)。调用方可记录 `error.diagnostics`，不应记录局部变量或原始组件输出。

```powershell
python -m pytest tests/test_experiment_report.py -q
```

离线测试用合成语料与模拟生成检查字段顺序/子集、论文隔离、精确引用、部分/缺失、未知统计、失败停止及脱敏；测试不读取真实.env、不调用API、不修改检索评测或冻结数据。后续真实开发检查见下节，尚无独立字段级质量评测。

## 2026-11-03 首次真实开发检查：未通过范围与覆盖验收

运行前固定范围为Transformer base、WMT2014 English-to-German、单模型，选择数据集/训练设置/结果三项，并预先对照原PDF第7–9页固定核对标准；预期和参考答案未发送给模型。复用247块既有向量快照，在单论文内执行Top-5混合检索、rrf_k=60。新生成3条查询向量，请求3次DeepSeek，均无重试。

三字段均返回`partial`，14条引用的编号、原文子串、块内偏移、论文与页码检查通过，但报告未达到目标实验的覆盖与范围要求：

- 数据集栏主要列出英德/英法成绩，缺约450万英德句对及BPE信息，内容越字段并混入英法任务。
- 训练栏包含big模型3.5天/300K步，未组成base实验的训练设置；base100K来自表3，但同时说明其关联仍不确定。
