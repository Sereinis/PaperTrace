# 论文分块向量化与本地缓存

## 功能与文件用途

`papertrace/embedding_cache.py` 接收现有 chunk 列表，调用 BGE-M3 适配层，保存内容缓存，生成保持输入顺序的向量快照。

`papertrace/embed_cli.py` 提供独立命令，读取一个或多个现有 chunk JSON，记录来源文件哈希与分块配置，再保存完整向量快照。不会重新解析 PDF，不改变现有关键词检索或评测协议。

`tests/test_embedding_cache.py` 与 `tests/test_embed_cli.py` 使用临时目录及模拟客户端验证复用、失效、异常与路径保护，不读取真实 `.env`、不调用外部 API。本说明是使用与数据契约文档，不是逐行源码解析稿。

## 使用方法

先按 README 生成 chunk JSON，并在本地配置硅基流动密钥。首次运行会把缺失文本发送给服务商，可能产生费用；默认不自动重试。

```powershell
python -m papertrace.embed_cli --chunks artifacts/attention-chunks.json --cache-dir artifacts/embedding-cache --output artifacts/attention-vectors.json
```

`--chunks` 接收多个文件，按命令中的文件顺序与文件内部 chunk 顺序合并；不同输入中的 chunk_id 也必须唯一。每个 chunk 必须包含非空的 chunk_id、document_id、text，以及正整数 page_number，其他合法 JSON 元数据原样保留。

`--model` 默认 `BAAI/bge-m3`，可显式选择 `Pro/BAAI/bge-m3`，不会自动切换。`--batch-size` 默认8，客户端允许1—32，不代表服务商保证所有批次均可处理。具体输入限制沿用向量化适配层，不自动截断原文。

为避免覆盖实验产物，命令拒绝已有输出文件，也拒绝输入与输出位于内容缓存目录内。第二次运行需使用新的输出路径，例如 `artifacts/attention-vectors-second.json`。缓存全部命中时不创建向量化客户端，因此无需可用密钥或网络。

## 缓存身份与复用规则

每个缓存文件对应一个唯一文本及模型配置。其文件名由规范化 JSON 的 SHA-256 生成，包含 schema_version、文本 UTF-8 摘要和完整向量化配置的身份，不把论文 ID 拼接到路径中。

配置包含服务商、接口地址、精确模型名、1024维、float编码及 `identity-v1` 输入处理约定。批次、超时和重试不改变向量语义，因此不参与身份。当前没有给文本添加指令、前缀、去空白或其他预处理。

相同模型和相同原文可以跨论文、跨页复用向量；同一批里的重复文本也只生成一次。文本、模型或输入处理约定改变时产生不同缓存。页码、章节、ID或偏移变化但文本不变时可复用向量，输出始终绑定当前 chunk 元数据，而不是使用旧页码。

缓存仅保存配置、文本摘要、向量与内容校验和，不保存密钥、请求头、原文或页码。校验和用于发现意外损坏，不是数字签名，不能抵御有意篡改。

托管模型可能在相同模型名下升级，当前接口没有可固定的权重版本；代码无法自动识别这类变化。需要重新建立实验基线时使用新的缓存目录，并记录重新生成条件，不把旧向量当作必然等同于新请求结果。

## 输出快照

顶层保存 schema_version、embedding_config、chunks_sha256、chunk_count、cache_stats、records；命令额外保存 source_files，包含各输入文件名、原始文件字节哈希及除 chunks 外的源元数据，例如分块参数。

chunks_sha256 对完整输入 chunk 列表按键排序、紧凑 UTF-8 JSON 计算，包含文本、元数据及列表顺序。它用于区分输入快照；内容缓存键则只关心文本与模型配置，两者用途不同。

每个 records 条目含 `chunk` 与 `embedding`。chunk 是原分块对象的独立副本，embedding 是对应的1024维向量；两者通过列表位置和内部 chunk_id 追踪。

cache_stats 按唯一文本计数：unique_text_count 为总唯一文本数，cache_hit_texts 为运行开始前命中的文本数，embedded_texts 为本次新生成的文本数，不是 HTTP 请求次数。缓存命中统计会随运行变化，整个输出文件不承诺重复运行字节一致。

完整快照包含论文原文，应和内容缓存一样放在被 Git 忽略的 artifacts 下。命令允许自定义位置，因此使用者仍需避免把产物放进公开仓库。

## 损坏与中断处理

先校验全部输入及所有已存在缓存，再请求缺失向量。缓存存在但JSON损坏、校验失败、身份不符、维度错误、非有限数值或零向量时明确失败，不静默重新请求计费。

请求成功后，先验证当前整批的数量和所有向量，再按条原子写入缓存。每个文件在目标同目录生成临时文件，写入、flush和fsync后用os.replace替换，异常时清理临时文件。它保护单文件不出现半个JSON，不提供全批事务或多进程锁。

后续批次或文件写入失败时不生成完整结果快照，但已写入的合法缓存保留，下次重跑可复用。已完成API请求但尚未写盘时发生进程退出，仍可能在重跑时重复计费；当前不承诺恰好一次处理。

缓存损坏时先定位并检查对应文件。恢复策略是使用新目录，或人工处理确定损坏的单个缓存；程序不会自动删除或清空目录。当前只面向单进程本地开发，不同时运行多个写入同一缓存/输出的命令，不提供并发合并、自动清理或版本迁移。

验证缓存位于 artifacts/embedding-cache-smoke-20261020，快照为 artifacts/embedding-smoke-20261020.json，均被Git忽略。未批量生成三篇论文的全部向量，不输出密钥、完整向量或原文。

该结果仅验证分块向量化与本地复用，不是向量检索质量评测。相似度搜索、查询向量化、检索方法对比和问答尚未实现。
