# 单实验报告验收与服务接入门槛

## 范围与状态

本文件区分算法内容验收、内部接口联调和上线条件，作为开发验收方案草案。门槛尚未完成人工确认，当前不构成报告验收通过记录。既有开发例的29项事实检查继续保留，不删除缺项、不把历史与局部输出拼为新报告。

当前能力是指定论文和实验范围的七字段证据报告，结果字段可用显式主体—成绩—条件图；不是全文实验自动发现、完整表格恢复或已验证的数值数据库。代码结构与引用定位检查不等于事实、范围和语义支持验证。

## 三个独立门槛

| 门槛 | 要求 | 当前状态 |
| --- | --- | --- |
| 内部接口联调 | 有界输入/预算、成功与安全失败契约、原始引用与审计可区分；联调响应保留未验证标记 | 单问题Python REST与Java调用已完成模拟联调；报告接口、报告审计/用量响应和完整失败分类尚未实现 |
| 开发报告内容验收 | 同一当前版本完整七字段运行，按预先固定的事实清单核对；范围错误、无依据结论和跨字段矛盾无未解决阻断项 | 未通过；2026-11-05已完成v10完整运行，仍有对照范围污染、训练及指标核心遗漏 |
| 线上使用 | 除内容范围外，完成权限隔离、API配置保护、请求配额/超时、服务访问控制及部署验证 | 未实现，不以本轮开发验证代替 |

内部接口骨架可采用模拟器联调，不需要先证明算法完美；这不等于允许将未经内容验收的输出标为可靠报告。对外质量说明、错误边界和验收结论独立于接口是否返回HTTP成功。

## 七字段最低检查范围

以下为通用检查范围，具体论文适用项和预期在生成前固定；不向生成器提供参考答案。不适用或候选未覆盖时保留明确边界，不按固定模板补造事实。

| 字段 | 必查范围 |
| --- | --- |
| 研究问题 | 具体目标任务、研究问题及必要动机；不把另一变体最佳成绩当研究目标 |
| 数据集 | 训练语料、已报告预处理、相关开发/测试集及用途；不把测试集用途与训练切分过程混淆 |
| 模型 | 目标变体和关键架构定义；共用设置需要适用依据，不默认所有变体相同 |
| 对照方法 | 当前任务下的相关方法、单模型/集成类别、文献比较来源；不推断为同配方重跑 |
| 训练设置 | 已报告硬件、步数/耗时、批次单位、优化器/调度及正则化参数和作用位置 |
| 评价指标 | 指标、划分、模型组成及必要评测/解码/选参条件；未知工具配置不补造 |
| 实验结果 | 同一条结果绑定模型/任务/数据集/划分/指标/值及必要条件，不借其他claim补引用 |

报告是否完整根据预先固定清单判断，而不是要求七字段一律`answered`。已知核心事实缺失时，`partial`可以是正确边界行为，但不能因此算该事实已覆盖。

## 问题分级与处理

| 级别 | 例子 | 处理与退出条件 |
| --- | --- | --- |
| 阻断：事实/范围错误 | big或英法信息进入目标事实；开发成绩当测试；引用不支持数值/条件；历史对照虚构为统一重跑；跨字段矛盾 | 修复受影响路径并保留原失败记录；局部核对后仍需当前版本完整验收 |
| 阻断：核心覆盖不足 | 已固定必查项被遗漏，包括只在引文出现却未展示的配置/条件 | 不以提示隔离或`partial`直接关闭；检查未召回、最终截断、未抽取、复核移除，修复或保留未通过 |
| 边界：来源或适用关系待核验 | BLEU工具版本不在候选；配置与变体关联不确定 | 明确候选不足或关联待核验，不称论文未报告；未知事实不进入已确认结论 |
| 非目标能力 | OCR、完整表格恢复、自动证明语义支持、全文穷尽性 | 作为当前范围限制，不为通过单个案例临时扩展 |

`answered`仅为模型自评，不能关闭阻断项。`keep`仅为模型复核，不能将`semantic_support`等标记升级为已验证。原始`missing_info_audit`同样不是事实；展示固定待核验提示只是隔离风险，并未解决具体缺口的可操作性。

## 验证流程与停止规则

1. 固定版本、字段、输入指纹、目标身份、必查项和调用上限；保留旧记录。开发例的既有29项清单不因输出遗漏而删减。
2. 离线检查实际查询、缓存命中和候选成员；参考证据只用于诊断，不手工塞进生产候选。候选保留不等于内容覆盖。
3. 仅对已定位的问题做一次有预算的局部回归。未改善时记录根因证据或待验证假设，转入方案评估，不自动循环重试。
4. 局部改善不替代完整验收。准备完整验证时使用同一版本直接生成七字段，不复用旧字段拼接；字段失败按既有契约停止，不把半份内容当成功报告。
5. 按固定清单逐项给出满足/部分/未覆盖/错误，另列范围阻断、未知边界与支持验证限制。不将候选数、测试数或模型状态换算为准确率。

当前仅在一个已观察开发例反复回归，不能形成泛化结论。未来扩展样本应先固定未参与修改的新论文/问题和参考依据，再运行；已观察的冻结检索测试集不重新称为未见测试。

## 服务接入约束（报告接口待实现）

业务后端保持Spring Boot，论文处理与检索/生成能力由Python内部REST服务承载。目前单问题接口已实现，以下七字段报告约束仍为待实现方案，不是当前单问题API的响应契约。

- 成功响应保留版本、输入指纹、七字段结果、精确引用、用量和未验证标记；最终事实只来自`qa.claims`，候选/审计不回灌成结论。
- 失败响应区分非法输入、检索失败、生成失败、契约失败、上下文超限；保留合法用量和安全诊断，不含密钥、原始服务端错误或半份成功报告。
- Java与Python两层不能各自自动重试而重复计费。完整七字段最多14次生成仅指引擎调用次数，不是token/账单上限；嵌入请求另算。
- 首版内部联调限可信本地输入，网络暴露、上传存储、认证、多租户及用户自填API配置需要单独实现与验收，不能直接开放现有适配器接收任意URL。

报告接口形状与任务超时策略仍需确定；现有单问题Java集成仅验证本机模拟链路，尚无线上的密钥管理或部署可用性结论。
